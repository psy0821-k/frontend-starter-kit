# 랜딩페이지 — 확정 요구사항

## 개요

`/`(루트)에 구현하는 Frontend Starter Platform의 메인 페이지. `docs/routing.md`가 정의한
루트 역할("Starter Platform의 소개와 주요 기능 안내, Starter/Template/Feature 탐색 시작점")을
그대로 구현한다. 별도 라우트(`/landing`)를 신설하지 않는다.

## Primary User

채용 담당자/면접관. "이 사람이 무엇을 만들 수 있는가"를 빠르게 파악하려는 방문자를
기준으로 톤을 잡는다 — 설명은 임팩트 중심, 기술적 디테일은 템플릿 상세 페이지로 위임한다.

## 최소 동작 시나리오

1. 방문자가 `/`에 진입하면 텍스트 설명(플랫폼 소개)을 먼저 본다.
2. 스크롤하면 "복사 붙여넣기로 사용하는 모습"을 보여주는 데모 비디오를 만난다.
3. 이어서 북마크 수 기준 인기 템플릿 3개를 캐러셀로 훑어보고, 카드의 바로가기 버튼으로
   `/templates/[id]` 상세 페이지로 이동한다.

## 구성 요소별 결정

### 1. 텍스트 설명 섹션

- 플랫폼이 무엇인지, 어떻게 쓰는지를 텍스트로 전달.
- 상세 톤/카피는 이번 인터뷰 범위 밖 — PRD 단계에서 컴포넌트 구조만 결정.

### 2. 데모 비디오 섹션

- 사용자가 사전에 직접 녹화한 mp4 파일을 정적 자산으로 업로드해 `<video>`로 재생.
- 비디오 파일 자체의 준비(녹화)는 이번 이슈 범위 밖 — 플레이스홀더 처리 여부는 PRD에서 결정.

### 3. 인기 템플릿 캐러셀

- **데이터**: `bookmarks` 테이블(마이그레이션 `014_bookmarks.sql`, `feat/bookmark-list-cards`에서 구현)
  기준 북마크 수 상위 3개 템플릿. 신규 집계 쿼리가 필요 — 기존 `get-starter-kits.ts`에는
  인기도 정렬 기능이 없음.
- **레이아웃**: 카드 왼쪽에 제목/사용 기술/카테고리/바로가기 버튼, 오른쪽에 이미지.
  이미지 비율은 1:1.1613(황금비) — 기존 카드 컴포넌트의 비율이 다르면 이 섹션 전용으로
  맞춘다.
- **바로가기 버튼**: `/templates/[id]` 상세 페이지로 이동 (기존 라우트 재사용, 신규 라우트 없음).
- **경계 조건**: 상위 템플릿이 3개 미만이면 있는 만큼만 표시. 집계 쿼리 실패(mock 폴백
  포함 기존 관례상 발생 가능) 시 캐러셀 섹션 자체를 렌더링하지 않음(에러 UI 없음).
- **인터랙션**: 캐러셀 자동/수동 전환 + 스크롤 진입 시 등장 애니메이션. 호버 회전·패럴랙스 등
  고급 인터랙션은 Out of Scope.

### 4. 반응형 — 모바일 퍼스트

- 모바일 레이아웃을 기준으로 먼저 설계하고, `sm:`/`md:`/`lg:` prefix로 점진 확대한다
  (`plan/CODING_CONVENTION.md` §7.6과 동일한 원칙 — 이 프로젝트의 기존 컨벤션을 그대로 따름).
- 캐러셀은 모바일에서 카드 1개씩 스와이프, 데스크톱에서 여러 개 노출 등 브레이크포인트별
  동작 차이가 있을 수 있음 — PRD 단계에서 구체화.
- 데모 비디오는 모바일에서 자동재생 대신 탭-투-플레이 등 데이터 사용량을 고려한 처리가
  필요한지 PRD에서 검토.

### 5. SEO/메타데이터

- `title`/`description`/OG 이미지 등 기본 메타태그를 설정한다(Next.js App Router의
  `generateMetadata`/`metadata` export 활용). 채용 담당자가 링크 공유·검색으로 진입할 수
  있는 첫 화면이므로 최소한의 메타태그는 이번 이슈 범위에 포함한다.
- 구체적인 카피(설명 문구)는 PRD 단계에서 확정.

### 6. 비디오 접근성

- `prefers-reduced-motion: reduce` 환경에서는 비디오 자동재생을 하지 않는다
  (`src/features/portfolio-landing/ui/terminal-hero.tsx`의 기존 패턴 참조).
- 기본값은 음소거 자동재생(또는 클릭 재생) — 소리 있는 자동재생은 하지 않는다.
- 자막 트랙 제공 여부는 비디오 콘텐츠 확정 후 PRD에서 결정.

### 7. 로딩 성능

- 비디오와 캐러셀 이미지가 초기 렌더링(LCP)을 막지 않도록 지연 로딩(`loading="lazy"`,
  비디오는 `preload="none"` 또는 `metadata`)을 적용한다.
- 히어로(텍스트 설명) 섹션만 우선 렌더링되고, 비디오/캐러셀은 뷰포트 진입 시점에
  로드되는 것을 목표로 한다.

## 용어 정의 (Ubiquitous Language)

| 용어                | 의미                                                                       |
| ------------------- | -------------------------------------------------------------------------- |
| 랜딩페이지          | `/`(루트)에 구현되는 플랫폼 메인 페이지. routing.md의 "메인 페이지"와 동일 |
| 인기 템플릿         | `bookmarks` 테이블 집계 기준 북마크 수 상위 템플릿(StarterKit)             |
| 데모 비디오         | 코드 복사 → 붙여넣기 사용 흐름을 보여주는 사전 녹화 mp4                    |
| 템플릿 카드(캐러셀) | 왼쪽 텍스트 정보 + 오른쪽 이미지(1:1.1613)로 구성된 캐러셀 아이템          |
