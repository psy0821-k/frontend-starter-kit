# 회원가입(auth/register) — 요구사항 명세

**작성일**: 2026-08-08 (v2: 2026-08-08 — Google 간편 가입 제거, 이름·개인정보 동의 추가 / v3: 2026-08-08 — UI 조정: 이름 필드를 폼 최상단으로 이동, 생년월일 필드 삭제)
**범위**: `/auth/register` 페이지 (이메일 회원가입만)
**상태**: 요구사항 확정, 구현 진행 중 (Supabase MCP 연결 후 최종 연동 예정)

---

## 1. 개요

`/auth/register`는 [docs/routing.md](../routing.md)에 정의된 인증 전용 독립 영역(`auth`)의 하위 페이지다. Supabase Auth를 인증 백엔드로 사용하며, 이메일/비밀번호 가입만 제공한다.

**v2 변경사항**: Google 간편 가입은 회원가입이 아닌 로그인(`/auth/login`)에서 제공하는 것으로 재분류되어 이 spec에서 제외한다. 대신 이름 필드와 개인정보 관련 법적 동의 절차가 추가된다.

**v3 변경사항(UI 조정)**: 이름 필드를 폼 최상단(이메일보다 앞)으로 이동. 생년월일 필드는 삭제한다 — 이번 스코프에서는 수집하지 않는다.

## 2. 인증 방식

- **이메일 + 비밀번호**만 지원 (Supabase Auth 기본 이메일 가입)
- Google OAuth 등 간편 로그인은 이 spec의 범위가 아니다 (§10 참조)

## 3. 폼 필드 구성

폼 상단부터 아래 순서로 배치한다.

| 순서 | 필드                  | 필수 여부 | 설명                                        |
| ---- | --------------------- | --------- | ------------------------------------------- |
| 1    | 이름                  | 필수      | 실명. 별도 형식 검증 없음(공백 아닌 문자열) |
| 2    | 이메일                | 필수      | Supabase Auth 계정 식별자                   |
| 3    | 비밀번호              | 필수      | §4 비밀번호 정책 적용                       |
| 4    | 비밀번호 확인         | 필수      | 비밀번호와 일치 여부 실시간 검증            |
| 5    | 닉네임                | 필수      | §5 닉네임 정책 적용                         |
| 6    | 이용약관 동의         | 필수      | §6 동의 항목 참조                           |
| 7    | 개인정보처리방침 동의 | 필수      | §6 동의 항목 참조                           |

생년월일 필드는 두지 않는다(v3에서 삭제).

## 4. 비밀번호 정책

- 최소 8자 이상
- 영문 + 숫자 + 특수문자 조합 필수 (대소문자 구분 없음)
- Zod 스키마로 검증하며, 형식이 틀리면 어떤 조건이 미충족인지 안내 문구로 표시
- **실시간 검증**: 타이핑 중(`onChange`)마다 즉시 피드백 (체크리스트 형태로 충족 조건 표시)
- **비밀번호 확인**: 비밀번호와 일치하지 않으면 타이핑 중 즉시 안내

## 5. 닉네임 정책

- 길이 제한 적용 (예: 2~20자 — 정확한 범위는 구현 시 확정)
- Supabase 대상 실시간 중복 확인 (디바운스 후 조회)

## 6. 개인정보 동의

가입 시점에 신규 개인정보(이메일, 이름, 닉네임)를 최초로 수집하므로, 개인정보보호법상 수집 시점 고지·동의 원칙에 따라 이 페이지에서 동의를 받는다. (로그인 페이지는 이미 동의한 사용자의 재인증이므로 별도 고지 불필요 — 별도 spec에서 다룸)

- **이용약관 동의**(필수), **개인정보처리방침 동의**(필수)를 각각 분리된 체크박스로 제공
- 상단에 "전체 동의" 일괄 체크박스를 두어 두 필수 항목을 한 번에 체크 가능
- 필수 동의 항목을 모두 체크하지 않으면 가입 제출 불가
- 약관 본문은 이번 단계에서 자리표시자(placeholder) 페이지로만 연결한다 (`/legal/terms`, `/legal/privacy` 등 경로는 구현 시 확정, 실제 법무 검토된 약관 문구는 이 spec의 범위가 아님 — 법적 책임이 있는 문서라 AI가 작성하지 않는다)

## 7. 이메일 인증

- Supabase 이메일 인증 사용 (가입 즉시 로그인 가능한 상태가 아님)
- 가입 성공 시 사용자는 **이메일 인증 안내 페이지**(`/auth/verify-email`)로 이동
- 인증 완료 전까지 로그인 불가

## 8. 에러 처리

- 이미 가입된 이메일로 가입 시도 시: **폼 제출 시 에러 메시지로 안내** (예: "이미 가입된 이메일입니다")
  - 보안상 이메일 존재 여부를 노출하는 트레이드오프가 있으나, UX를 우선하는 정책으로 채택
- 에러 메시지는 `src/shared/api/error.ts`의 `ApiError` 클래스 및 `src/types/api.ts`의 `ApiErrorCode` 유니온 체계를 따른다. Supabase 에러 코드는 BFF(Route Handler) 계층에서 이 유니온으로 매핑해 흡수한다.

## 9. 가입 후 흐름

1. 이름/이메일/비밀번호/닉네임 입력 + 필수 동의 체크 → 제출
2. Supabase 계정 생성 + 인증 메일 발송
3. `/auth/verify-email`로 이동, "인증 메일을 보냈습니다" 안내
4. 이메일 인증 완료 후 로그인 가능

## 10. 용어 정의 (Ubiquitous Language)

| 용어        | 정의                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| 닉네임      | 서비스 내 표시 이름. 로그인 식별자(이메일)·실명(이름)과 별개                 |
| 실시간 검증 | 사용자가 입력 중(`onChange`)일 때 즉시 수행되는 클라이언트 측 유효성 검사    |
| 전체 동의   | 이용약관·개인정보처리방침 등 필수 동의 항목을 한 번에 체크하는 일괄 체크박스 |

## 11. 향후 작업 (Out of Scope, 현 단계)

- Supabase MCP 연결 및 실제 계정 생성/조회 연동 (이 spec은 요구사항 정의까지만 다룸, 코드 로직은 이미 작성됨)
- 닉네임 정확한 길이 범위 확정
- Google 등 OAuth 간편 로그인 — `/auth/login`에서 별도 spec으로 다룸
- 비밀번호 재설정 등 다른 auth 하위 페이지 spec
- 이용약관·개인정보처리방침 실제 본문 작성 (법무 검토 필요, AI가 작성하지 않음)
- 마케팅 정보 수신 동의 등 선택 동의 항목 (이번 스코프는 필수 동의만)
